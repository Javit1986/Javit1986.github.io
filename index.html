Mercado Pago → ARCA

Detecta cada ingreso de dinero en Mercado Pago y emite sola la factura electrónica en ARCA (la ex AFIP). Reemplazó un proceso que se hacía a mano, factura por factura.

Detects every incoming payment in Mercado Pago and automatically issues the electronic invoice with ARCA, Argentina's tax authority. It replaced a process done by hand, one invoice at a time.

El problemaThe problem

En un comercio la plata entra por muchos caminos: QR, links de cobro y, sobre todo, transferencias al alias. Cada ingreso tiene que terminar facturado. Lo difícil: Mercado Pago no avisa cuando llega una transferencia directa. Hay que descubrirla en un reporte que tarda horas en generarse.

Money reaches a shop through many channels: QR codes, payment links and, above all, direct bank transfers. Every one of them must be invoiced. The hard part: Mercado Pago sends no event for direct transfers. They have to be found in a report that takes hours to generate.

Lo que construíWhat I built

Webhooks firmados para los pagos y sondeo del reporte para las transferencias. Cada ingreso se registra una sola vez, se decide si va en factura individual o en la consolidada del día, y un único worker emite las Facturas B en orden, con PDF y QR fiscal. Es multi-tenant: otro negocio se da de alta solo, sin tocar código.

Signed webhooks for payments and report polling for transfers. Each movement is recorded exactly once, routed to an individual invoice or the daily consolidated one, and a single worker issues invoices in strict order, with PDF and fiscal QR code. It's multi-tenant: a new business onboards itself with no code changes.

Mi rolMy role

Todo, en solitario: reglas de negocio, API, panel, modelo de datos, Docker y la operación en producción, incluidas las auditorías contra datos reales.

All of it, solo: business rules, API, admin panel, data model, Docker and production operations, including audits against real data.

      Problemas que resolvíProblems I solved

      Facturar en orden estricto con ingresos simultáneosStrictly ordered invoicing under concurrent income

      Problema. ARCA exige numeración correlativa. Los ingresos llegan en ráfagas y por dos canales a la vez; emitir en paralelo genera rechazos y huecos.

      Solución. Una cola en una tabla de PostgreSQL y un único worker que toma el trabajo más antiguo y lo marca dentro de la misma transacción. Sin Redis ni RabbitMQ: cero infraestructura extra y el estado se inspecciona con SQL.

      Problem. ARCA requires sequential invoice numbers. Income arrives in bursts through two channels at once; issuing in parallel causes rejections and gaps.

      Solution. A queue in a PostgreSQL table and a single worker that claims the oldest job inside the same transaction. No Redis or RabbitMQ: zero extra infrastructure and the state is inspectable with SQL.

      Una factura con fecha equivocada: el síntoma no era la causaAn invoice with the wrong date: the symptom wasn't the cause

      Problema. El PDF mostraba un día y ARCA tenía autorizada la factura con el siguiente. Parecía un bug de zona horaria ya corregido.

      Causa. La fecha real enviada a ARCA nunca se guardaba: el PDF la recalculaba con otra fórmula. Corregí la raíz con una única fuente de verdad y consulté a ARCA en modo lectura cada factura histórica para encontrar cualquier otra afectada.

      Problem. The PDF showed one date while ARCA had authorized the invoice on the next day. It looked like an already-fixed timezone bug.

      Cause. The actual date sent to ARCA was never stored; the PDF recomputed it with a different formula. I fixed the root with a single source of truth and queried ARCA read-only for every past invoice to find any other affected one.

      Un contador que se desincronizaba: rediseñar en vez de parcharA drifting counter: redesign instead of patching

      Problema. Una auditoría con datos reales encontró facturas consolidadas cuyo monto no coincidía con la suma de sus movimientos, tras una caída del servidor.

      Solución. Eliminé el contador. Ahora el monto se calcula sumando los movimientos reales en la misma transacción del cierre: por construcción no puede desincronizarse. Las correcciones se aplicaron con scripts en dry-run por defecto y nunca se tocó una factura ya emitida.

      Problem. An audit against real data found consolidated invoices whose amount didn't match the sum of their movements, after a server outage.

      Solution. I removed the counter. The amount is now computed from the real movements inside the closing transaction, so it cannot drift by construction. Fixes ran through scripts that default to dry-run, and no issued invoice was ever mutated.

      Dinero que sale no es una ventaMoney going out is not a sale

      Problema. Pagos a proveedores y transferencias enviadas se estaban registrando como ingresos. Y en ciertas operaciones Mercado Pago informa como pagador al propio titular.

      Solución. Clasificar por la forma del payload comparando pagador y cobrador contra la cuenta real, consultar el pago en vivo a la API y reconciliar el histórico con scripts idempotentes sin tocar comprobantes emitidos.

      Problem. Supplier payments and outgoing transfers were being recorded as income. On some operations Mercado Pago also reports the account owner as the payer.

      Solution. Classify by payload shape, comparing payer and collector against the real account, query the payment live from the API, and reconcile history with idempotent scripts without touching issued invoices.

async function claimNextJob() {
  return prisma.$transaction(async (tx) => {
    const next = await tx.invoiceJob.findFirst({
      where: { status: "PENDING" },
      orderBy: { createdAt: "asc" },
    });
    if (!next) return null;
    return tx.invoiceJob.update({
      where: { id: next.id },
      data: { status: "PROCESSING" },
      include: { tenant: true, movements: { select: { occurredAt: true } } },
    });
  });
}

      Eterno Instante

      Plataforma para que fotógrafos de playa, calle y eventos vendan sus fotos en el momento: el cliente encuentra su sesión, paga con Mercado Pago y descarga el original.

      A platform that lets beach, street and event photographers sell their photos on the spot: customers find their session, pay with Mercado Pago and download the original.

      El problemaThe problem

      Un fotógrafo de playa saca cientos de fotos por jornada a gente que sigue caminando. Imprimir es caro y lento, mandar por WhatsApp no asegura el cobro, y la mayoría de las ventas se pierde. Además hay que organizar miles de archivos y evitar que alguien se lleve las fotos sin pagar.

      A beach photographer takes hundreds of shots a day of people who keep walking. Printing is slow and expensive, WhatsApp doesn't guarantee payment, and most sales are lost. On top of that, thousands of files need organizing and nobody should walk away with photos they didn't pay for.

      Lo que construíWhat I built

      El fotógrafo marca la sesión desde el celular y vuelca la tarjeta de memoria. Un worker en Python asocia cada foto a su sesión por la hora EXIF y genera cinco variantes. El cliente ve las fotos protegidas con el efecto lupa, paga y descarga con un link firmado que vence. Paneles por rol para fotógrafo, mostrador y sysadmin.

      The photographer marks the session on their phone and dumps the memory card. A Python worker matches each photo to its session by EXIF time and renders five variants. Customers browse protected previews with a magnifier effect, pay, and download through a signed, expiring link. Role-based panels for photographer, counter staff and sysadmin.

        Problemas que resolvíProblems I solved

        Cuentas saldadas que seguían morosasSettled accounts still flagged as overdue

        Causa. Por cada deuda, el cálculo sólo miraba los pagos anteriores a ella; un pago posterior nunca la cancelaba.

        Solución. Recorrer el historial en orden con una cola FIFO: cada deuda entra, cada pago consume desde el frente. Cuando la cola se vacía, la antigüedad se reinicia sola.

        Cause. For each debt, the calculation only looked at earlier payments; a later payment never settled it.

        Solution. Walk the history in order with a FIFO queue: each debt is enqueued, each payment consumes from the front. When the queue empties, the aging resets by itself.

        Deuda y pago con la misma fecha y horaA debt and a payment with the same timestamp

        Problema. Un cliente real con saldo $0 seguía con "deuda antigua". Al migrar el cuaderno, los movimientos se cargaron a las 12:00 y el desempate por id podía procesar el pago antes que la deuda.

        Solución. Un criterio explícito en el ORDER BY: ante empate, la deuda va primero. El orden de los datos es parte de la lógica de negocio.

        Problem. A real customer with a $0 balance still showed "old debt". Migrated paper entries were stored at 12:00, and tie-breaking by id could process the payment before the debt.

        Solution. An explicit ORDER BY criterion: on a tie, the debt goes first. Data ordering is part of the business logic.

        Publicar a internet desde una PC del comercioExposing a shop PC to the internet

        Decisión. Evalué VPS, DDNS y túnel; elegí Cloudflare Tunnel: sin abrir puertos ni depender de IP fija.

        Endurecimiento. helmet, CORS por variable de entorno, límite de 8 intentos de login cada 15 minutos por IP y el servidor no arranca si falta la configuración.

        Decision. I compared a VPS, DDNS and a tunnel, and picked Cloudflare Tunnel: no open ports, no fixed IP needed.

        Hardening. helmet, env-based CORS, login limited to 8 attempts per 15 minutes per IP, and the server refuses to start without configuration.

        function fechaDeudaMasAntigua(cuenta_id) {
  const movimientos = movimientoRepo.listarPorCuenta(cuenta_id).slice().reverse();
  const colaDeudas = [];
  for (const mov of movimientos) {
    if (mov.tipo === 'deuda') {
      colaDeudas.push({ fecha: mov.fecha, hora: mov.hora, restante: mov.monto });
      continue;
    }
    // un pago cancela deudas empezando por la más antigua pendiente
    let pagoRestante = mov.monto;
    while (pagoRestante > 0 && colaDeudas.length > 0) {
      const masAntigua = colaDeudas[0];
      if (masAntigua.restante <= pagoRestante) {
        pagoRestante -= masAntigua.restante;
        colaDeudas.shift();
      } else {
        masAntigua.restante -= pagoRestante;
        pagoRestante = 0;
      }
    }
  }
  if (colaDeudas.length === 0) return null; // sin deuda: la alerta se reinicia sola
  return colaDeudas[0];
}
